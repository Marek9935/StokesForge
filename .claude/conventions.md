# Conventions by domain

Detailed rules moved out of `CLAUDE.md` so they are loaded only when needed.
They carry the same weight as those of `CLAUDE.md`: read the section of the
domain **before** writing code. Most of them are also locked by a guard in
`stokesforge-app/tests/guards.rs` or `labels.rs`; a green guard does not
excuse you from the rule (it only sees what it looks for).

## Application (`stokesforge-app` and `stokesforge-app-state`): building blocks and guards

**Two crates, one boundary held by the compiler (#263).** `stokesforge-app-state` holds everything the application decides without drawing it: `state.rs` + `state/` (`AppState`, `Action`), `selection.rs`, `preferences.rs`, `analysis.rs`, `analysis_recent.rs`, `object_manager.rs`, `object_drag.rs`, `history_text.rs`, `quantities.rs`, `user_colors.rs`, `object_format.rs`, `text_format.rs`, `errors.rs`, `i18n.rs` + `i18n/` (the `.ftl` catalogs and `tr!`) and `file_picker.rs`; it has **no** egui/eframe/winit/wgpu dependency (`tests/no_ui_dependency.rs`, allowlist). `stokesforge-app` keeps `main.rs`, `app.rs`, `app/`, `theme.rs`, `icons.rs`, `field_state.rs`, `number_field.rs`, `toolbar.rs`, `list_frame.rs`, `tree_lines.rs`, `color_picker.rs`: everything that names an egui type. Interface logic that is decided goes in `stokesforge-app-state` (never `use egui`: the compiler refuses), drawing or a gesture goes in `stokesforge-app`. Imports are explicit (`use stokesforge_app_state::state::Action;`), with no re-export at the root, except `tr!` (`use stokesforge_app_state::tr;`). The system clipboard (`stokesforge-clipboard`) pulls in winit: the state keeps only neutral bytes (`state::FigureBytes`, an `ExportFormat` and its bytes), `app/figure_copy.rs` translates them to MIME types and phrases the error (`clipboard_error_message`). **`cfg(test)` pitfall**: `cfg(test)` applies only to the tests of the crate that carries it. What the state isolates under `cfg(test)` (preferences path `preferences::default_path`, starting language `i18n::startup_language`, `set_object_manager_open_for_test`) is therefore isolated under the `test-support` feature as well, which the dev-dependency of `stokesforge-app` enables: without it, the app tests (which build an `AppState` with `new`) would read and write the real `preferences.json` (locked by `stokesforge-app/tests/preferences_isolation.rs`). The integration tests of `app-state` do not see `cfg(test)` either: a dev-dependency of the crate on itself enables `test-support` (`tests/isolation_test_support.rs`, #329), without which `cargo test -p stokesforge-app-state` alone reads the real `preferences.json`. Never `test-support` in a normal build or in a `[dependencies]`. `fl!` reads the `i18n.toml` of the **calling** crate: the two `i18n.toml` files set the same `domain = "stokesforge_app"` and the one of the app points to the catalog of `stokesforge-app-state/i18n`.

A drop target lights up its window border through the `file_drop` marker (`set_drop_target`, read by `show_window_in_layer`, the maximized area and the detached tab), with `theme::drop_target_stroke`, never a `rect_stroke` in the content (#386).

Transitions #72–#73: native Wayland is the default, `STOKESFORGE_X11=1` forces
X11; the `vendor/winit` and `vendor/smithay-clipboard` patches, outside the
workspace, share the drop receiver and the clipboard between viewports.
Choice, targeted `rustfmt` commands, manual verification and removal:
`vendor/winit/STOKESFORGE.md`. The exact parser and channel are tested by
`stokesforge-app/tests/wayland_{uri,bridge}.rs`. Frame starvation (#457): Wayland
has no occlusion event, so the vendored winit infers `Occluded` from a frame
callback that does not come while a redraw is wanted, only for a window that opts in with
`WindowExtWayland::set_reports_occlusion` (the root, on its first pass; never a detached
window: a reported window gets no pass and its input is dropped) (`frame_starvation.rs`, pure,
`tests/wayland_frame_starvation.rs`); that is what lets eframe keep running a
covered root, so a detached window may be maximised over it (Page Layout Mode).
Never a periodic wake for it (#104). Handing a gesture to the OS (`ViewportCommand::StartDrag` / `BeginResize`) goes only through `app/os_gesture.rs` (guard `no_os_gesture_command_outside_the_helper`): on Wayland the compositor keeps the button release, so the helper plays it for egui at the head of the next pass of that viewport (`Plugin::input_hook`); a plain send leaves the title "dragged", every second grab does nothing and hover extends the column selection (#457). Recheck on any eframe upgrade; real-compositor
proof: `tests/wayland_covered_root.rs` (manual, headless mutter, GL backend).
The empty graph goes through `AddGraph`; `SessionHandle::new_project`, like
`load`, replaces the identity and empties the history after confirmation in the UI.

- `stokesforge-app`: `app.rs` split (work package #115, #116–#124 done) — rule adopted: **real modules** in `src/app/`, one per surface (module → role table in `docs/application/shell-and-code.md`, § Code split), with explicit imports, minimal visibility (`pub(super)` between `app` modules); no `use …::*` outside test code (`no_global_import_outside_tests`, `tests/guards.rs`, no exemption); **`app.rs` keeps only the orchestration** of the frame (`StokesForgeApp` and `new`, `ui()` and the panel order, `collect_shortcuts`, deferred application of actions, blocking confirmations, draining of detached windows) — a menu entry goes in `app/menus.rs`, window code in `app/window_*.rs`, a new surface in its own module (model: `object_manager.rs`, `toolbar.rs`, `app/dialogs.rs`). Common building blocks: `app/dialogs.rs` (`modal_dialog`, `modal_dialog_with`, `modal_wizard`, `modal_live_settings`, `modal_read_only`, `modal_confirm`, `modal_save_changes`, `modal_alert`), `app/tab_strip.rs` (`tab_strip`), `app/shortcuts.rs` (`SHORTCUT_*`), `app/tab.rs` (`Tab`), `app/window_chrome.rs` (frame, `show_window_in_layer`). **Tests follow their code** (`tests` module of the surface; the one of `app.rs` exercises only the orchestration) and are reread at every restructuring: scope set by the `perimetre` agent (Opus), tests written by Sonnet, witnesses verified by mutation (`CLAUDE.md`, "Delegation and model choice"). Giant functions are split in place (#124), never with a move: keep the nesting of egui Ui/IDs and the order of events; private painting contexts group only the data or borrows useful to the frame. All the guards that read the code go through a single reader, `stokesforge-app/tests/support/sources.rs` (all `src/` **of both crates**, recursive, the sources of `stokesforge-app-state` under the `app-state/` prefix; functions looked up by name; never `include_str!` nor a named file, #116, #263).
- `stokesforge-app`: every color setting goes through `color_picker::color_field` with the color's usage (`ColorUsage::Curves`/`Text`/`Background`) and the `PickerEnv` of the saved colors, never through a `#RRGGBB` text field. In a toolbar, the swatch is a small square preceded by an icon (`color_icon_button`, #89); in a form, `color_field` (label + square). Empty color = automatic, drawn as a square crossed by a red line; opacity as `#RRGGBBAA`; automatic text and scales follow `stokesforge_render::color::auto_ink` (white on a dark background).
- `stokesforge-app`: every window goes through the common building block — `show_window_in_layer` (`app/window_chrome.rs`) for a content window, `modal_dialog_with` (`app/dialogs.rs`) for a dialog, `modal_wizard` for a wizard, `modal_live_settings` (Close only, focus on the first field, size by class) for settings applied live (Preferences), `modal_read_only` (Close only) for a window that changes nothing, `modal_confirm` / `modal_save_changes` / `modal_alert` for a confirmation, the "Discard Changes · Cancel · Save" trio and a serious failure (#229; only for what Ctrl+Z cannot undo, drawn from `app/confirmations.rs`) (same `modal_frame` frame, same title bar, same blocking as the graph properties; ordered footer, message area — error from `fail` while a dialog is open, otherwise the reason the main button is disabled, carried by `DialogFooter::gated` (#226) —, initial focus and remembered geometry handled by the building block, #228); each modal window has a **nature** (`DialogNature`, S-F11, #300) that sets the footer, the size class (Small 480 x 170, Medium 480 x 420, Large 640 x 500), the initial focus and the default button: an interactive window takes a class, or a free size justified by `// FREE-SIZE(#300): <justification>` right before it (`no_free_size_without_justification`); a window without rich interaction (choice, read-only, confirmation, alert) may take the size of its content without justification; a new window goes into `docs/windows.md` with its `stokesforge_…` identifier (`the_window_catalog_and_the_code_agree`); never a raw `egui::Window`, even for a step-by-step wizard (locked by the test `no_window_is_a_raw_egui_window`). Existing code that deviates is not a model.
- `stokesforge-app`: dimmed text is reserved for the **secondary**, through two functions of `theme.rs`, never a `.weak()` written in place (`no_weak_outside_the_theme`, #392): `theme::secondary_text` (slightly smaller than body, 11 pt: help, reason, technical detail under a sentence) and `theme::dimmed_text` (normal size: empty state, "Calculating…", label beside a result); the content that a dialog or a read-only window wants read is in normal text (`docs/interface-standard.md`, § Windows and dialogs, "Dimmed text"). Copying the `.weak()` of a neighboring dialog is not a justification: the error detail of a save alert is dimmed because it is secondary, not because it is an alert.
- `stokesforge-app`: every icon goes through `icons::icon_image` / `icon_button` (Phosphor duotone, color role `IconRole`, `tr!` tooltip mandatory), never through a Unicode glyph or an emoji; color is rare, rules in `docs/icons.md` (locked by `no_icon_outside_the_component`). **Every action has its logo** (#110): a polished icon if it is in a fixed bar, the standard two-letter family logo otherwise (its template is still to come); this does not force display in the menus.
- `stokesforge-app`: every interface text goes through `tr!` with a key of the `en` catalog, written according to `docs/ui-texts.md`; never a literal (locked by `no_hardcoded_label`, including the `set_title` titles and the visible `add_filter` names of file dialogs, #127; technical extensions and format acronyms preserved). Every key is written **in both** catalogs (`en` and `fr`) in the same commit (completeness is blocking). No exemption: the guard is absolute (#48), and a catalog key that no call uses fails `no_catalog_key_is_dead` (`tests/labels.rs`: the catalog is in `stokesforge-app-state`, but the menus are written in `stokesforge-app`, hence the reading of both).
- `stokesforge-app`: a toolbar is a variant of `toolbar::ToolbarId` whose content is written in `toolbar::bar_contents` with `ToolbarButton`s (icon of the common component, `tr!` tooltip) that push the `Action`s of the menus; never a second execution path nor a panel placed beside it. The bars are **fixed** (#108): content and place frozen in the code (`ToolbarId::row`), no move and no floating mode; only their visibility (View menu) lives in `preferences.json`, not in the `.stf`. `Tools` and `Text` are always drawn, buttons disabled with a tooltip when no window is concerned. The text format (`ToolbarId::Text`) writes Typst tags into the text through `text_format::apply` for bold, italic, color and the size of a passage; the **font** (and, for a title or the legend, the size) is a field of the zone (`TextFont`, `AnnotationSpec::font`, #77/#78), set by `StokesForgeApp::format_zone` — never a `#text(font: …)` tag in the content.
- `stokesforge-app`: common appearance (#169) — a set of tabs (pages, sheets, axes) goes through `tab_strip` + `TabStripSide`, never through a row of buttons (one level: `Top`; two levels: primary `Top`, secondary `Left`, fixed, only the content scrolls, S-L9, #393); a selectable list or tree entry goes through `list_row` / `ListRowBackground` (`app/list_row.rs`, full-width row with an accent rule); a two-state setting that must show which state is on is a `state_toggle` (`app/state_toggle.rs`, #426): ONE button, one hit area, both labels always visible and fixed, the current state highlighted, a click anywhere switches, the whole button outlined on hover with the theme's hovered stroke (`paint_hover_outline`, also used by the on/off Snap button); never a button that renames itself, never two clickable halves; egui's selectable button stays for the exclusive choices of a menu, a drop-down list or the color picker (`no_selectable_button_outside_a_menu`). Bold through `theme::bold` only (`strong()` forbidden); **four text levels** named in `theme.rs` (#170): section title `theme::section_heading` (bold, normal size; `theme::section_title` places it with its space, without a `separator()` right before, `no_separator_before_a_section_title`), table header `theme::table_header` (bold, small size), secondary text `theme::secondary_text` (dimmed, slightly smaller than body, 11 pt), dimmed text `theme::dimmed_text` (dimmed, normal size) — never `bold(…).small()` nor `.weak()` written in place (`no_small_bold_outside_the_theme`, `no_weak_outside_the_theme`); **a single row height** `list_row::LIST_ROW_HEIGHT` (24 pt, #170) for `list_row` and for any composed row, set in its `ui.horizontal` by `with_list_row_height` (or `raise_to_list_row_height` / `restore_row_height` around a `show_header`), without a new sub-`Ui`; a decorative step separator is a dimmed icon (`icon_image` + `help_icon_tint`), not a glyph; state and chrome colors through `theme.rs` or the `Visuals`, no `Color32::from_…` outside `theme.rs` and `color_picker.rs` (`no_hardcoded_color_outside_the_theme`); a form is a two-column grid through `app/form.rs` (`form`, `Form::row`/`checkbox`/`note`/`section`, #227); never a collapsible section (S-L5) except the "Advanced" block of `Form::collapsible` (S-L8, #344: closed by default, at the bottom of its section, settings all Auto by default, its rows in the same grid; a common setting or one without Auto does not go there), a fixed exclusive choice through `choice` (radios for 2–3 options, list from 4), a menu choice through `menu_sections::menu_choice` (check mark only), the toggle choice in boxed texts `toggle_texts` reserved for the row of gestures of the analysis preview (exception S-K7, marker `TOOL-IN-WINDOW(#299)`), widths `theme::FieldWidth`, gaps `theme::SPACE_ITEM`/`SPACE_SECTION` and never `add_space(<number>)` (`no_literal_add_space_outside_the_theme`).
- `stokesforge-app`: every workspace key consumer (grid, Project Manager, any shortcut that acts on the main window's content and is painted before the dialogs) checks `!dialogs::modal_shown(ctx)` (#406); `focus_free` alone is not enough, egui drops the focus on Esc before the pass. Test it with a bench that paints the workspace then a modal in the same frame.
- `stokesforge-app-state`: a save or a gesture that may replace the project (`save`, `request_unsaved`) commits the open entries (cell, header field, note) in `AppState` first (`commit_open_entries`, #465/#466); never rely on a focus-loss action of the grid, since `blocking_confirmations` clears the actions: the grid and note field end a "click elsewhere" through the state (`commit_edit`, `commit_note_edit`), not by pushing an action. The shell does the same for the entries of detached windows (`commit_view_entries`, on Save, Save As, New, Open, Quit), which also closes the egui-side graph text editors through `commit_open_text_editors`. A refused entry stays open and is left out; autosave never commits.
- `stokesforge-app`: a field that opens in place goes through `app/inplace_edit.rs` (#224, contract S-T4: everything selected, Enter/click elsewhere commit, Escape cancels, Tab commits and moves to the next); a number input is read by `stokesforge_core::number_format::parse_input` (decimal comma, #223), never `parse::<f64>`; the tick separator is `PlotSpec::decimal_comma`.
- `stokesforge-app`: cell input and paste (#258): **a single rule** "text → cell value", `stokesforge_core::ValueBlock::from_texts(kind, &[&str]) -> (bloc, promoting)` — input (`commit_cell`) and paste (`value_block_from_tsv_column`) call it, never a second implementation in the app nor a detour through `MixedCell::from_text` (which keeps `inf`/`nan` as read, rule C2 of the type conversion). `inf`, `nan` and `1e400` typed or pasted stay text; dates are read only in a `DateTime` column. A paste that overwrites a `Mixed` column calls the repromotion (`auto_promote_mixed_column_if_all_numeric`) before closing its group, and stays one history entry.
- `stokesforge-app`: every number input goes through `number_field::number_field` and a quantity of `quantities.rs` (#220); neither `DragValue` nor `Slider` (`no_numeric_field_outside_the_building_block`). An input defect (unreadable, out of range) is drawn by `field_state` (#219), never by hand.
- `stokesforge-app`: behavior standard (#217) — fields, messages, dialogs, confirmations, disabling, keyboard and mouse follow `docs/interface-standard.md`, the single source (codes `S-N1`, `S-F3`… and readable names: rule index of the page). Each section there is *in place* or *planned* (#219–#232): a planned rule already applies to all new code; a planned building block or guard does not exist yet. The commit that delivers one moves it to *in place* and updates the skills.
- `stokesforge-app`: every expanded tree (Object Manager, Project Manager) draws its L-shaped connectors through `tree_lines` (`begin_tree`, `tree_children`, `TreeBranch::mark`), never through egui's indent line (#112).
- `stokesforge-app`: the look of the scroll bars (width, color) comes **only** from `theme::scroll_style`, set globally by `theme::install`; never a local `ScrollStyle` (locked by the test `no_scroll_style_outside_the_theme`). The room taken by a bar is read through `theme::scroll_bar_allocated_width`. A page that scrolls uses `theme::page_scroll_area()` (end margin `SPACE_SECTION`, #347); a raw `ScrollArea::vertical()`/`::both()` (tree, table, canvas, computed height) carries `// RAW-SCROLL(#347): <why>` (guard `no_raw_scroll_area_without_justification`).
- Configuration folder (#332): **a single rule**, `stokesforge_import::config_dir::config_dir()` — the `STOKESFORGE_CONFIG_DIR` variable if it is set and not empty (that folder as is, no suffix), otherwise `directories::ProjectDirs::from("", "", "StokesForge")`. It applies in production too (portable installation). Preferences, colors, recipes and recent import files derive from it; recovery is `recovery_dir()` (`<variable>/recovery`, otherwise `data_dir()/recovery`). `ProjectDirs::from` is called **only** by this module (`stokesforge-arch-guard/tests/config_dir.rs`): a new profile path goes through `config_dir()`. A test that redirects the folder sets `STOKESFORGE_CONFIG_DIR` **and** `XDG_CONFIG_HOME` (`directories` honors only the latter, and only on Linux: on Windows, `XDG_CONFIG_HOME` alone let the tests write into the real `%APPDATA%\StokesForge`), under a lock if the value is restored, or once per process (`OnceLock`); models: `isolate_recipe_store` (`stokesforge-app-state/tests/shell.rs`), `hermetic_configuration` (`stokesforge-script/tests/script.rs`). The `config_dir_from(Option<OsString>)` forms are tested without `set_var`.
- `stokesforge-app-state`: a file dialog is a `file_picker::PickRequest`, and every request says which default folder it follows (`PickRequest::folder_kind`, exhaustive, no `_`, #148); the starting folder comes from `AppState::folder_candidates` (session memory, Preferences default, fallback) and is looked up on the picker's thread (`is_dir`, `set_directory`), never on the interface thread. Only a file dialog's answer feeds the session memory (`remember_picked_folder`). `rfd::` stays in `file_picker.rs`; tests inject the picker (`start_with`, `start_resolving`, `start_fake`), never a real dialog.
- Grid entry row (#440): the empty row always shown below the last data row is UI only. `AppState::row_count` keeps counting model rows; navigation and selection use `AppState::entry_row(sheet)` (never `row_count` plus one), column selections and Ctrl+A never contain it, and writing in it goes through the ordinary `SetCells` (no `InsertRows`). `Action::CommitCellAndAdvance` moves the cursor in its handler, after the commit is accepted.
- Window identity (#388): **every** `ViewportBuilder` starts from `app_logo::viewport()` (`stokesforge-app/src/app_logo.rs`), which sets the `app_id` `stokesforge` (the name of the desktop entry `install-linux.sh` writes); a bare `ViewportBuilder::default()` is refused by `no_viewport_without_identity`. egui copies the icon to child windows but not the id, hence the single door. The main window adds the icon through `main_viewport`. **The logo is read only at run time**, from `<exe dir>/share/icons/hicolor/256x256/apps/stokesforge.png` (installed by `scripts/logo-dist.sh` in official builds); never `include_bytes!` it, never name `assets/logo` in code (`logo_boundary`): a build without the folder must stay the same code. A missing or unreadable file degrades (empty window icon, no logo in About, one stderr line, invariant 10). The About texture comes from `app_logo::texture_image` (straight alpha, not `ColorImage::from(IconData)`) and is created once at the first opening.

## Object Manager, fixed panels, menus

Accessibility (#170): a hand-painted target publishes its label and its
state through `Response::widget_info`, like egui widgets. The layer
badges announce their number and their selection; the handles of floating
and detached windows announce their resize direction. The
tests read the AccessKit nodes actually published, as close to the surface as possible.

Object Manager (#81–85): `object_manager.rs` projects the graph,
`app/object_manager_ui.rs` draws the tree (#121), the selection
stays in `GraphView` (same view in a detached window). Linked texts
(titles, legend) are **never** listed there (#214): they are edited by
double-click on the figure or in the properties; "Objects" contains only
free objects (free text, shapes), collapsed by default, absent when empty.
Scales ("Axes" group under the layer, collapsed by default #138, one row per axis, check box = `AxisSpec::visible`, #111)
have their own twin toggle (`Action::SetObjectManagerShowScales`) and are
not driven by the graph/layer check boxes. The filters live in
`object_tree_with_selection`. The view settings (#139) go through the
common menu `object_manager_settings_menu` (display and background, disabled if the panel is
closed), the `Action`s and `preferences::ObjectManagerSettings`, the single table of
defaults. Objects have their collapsible section per graph/layer; the initial
collapse never replaces the current egui state, even after Reset.
The detached model carries all the settings and wakes its viewport if
only those change. The toggles reuse
`EditPlotSpec`, whose history reason stays a data item. The swatches
call `series_swatch`, shared with the legend.

Fixed panels (#100): PM on the left, OM on the right, console at the bottom; visibility
through View, collapse distinct from hiding, no internal floating. The
`panel_header` frame (`app/window_chrome.rs`) shares the icon cells of
content windows with a compact font. The horizontal order of the buttons
depends on the side: collapse toward the workspace, detach toward the outside.
The expanded console keeps Collapse then Detach side by side on the left (#142). The collapsed and detached state of the three panels and the size and position of their window are remembered between launches (#148: `app/panel_memory.rs`, pure rules in `stokesforge-app-state/src/panel_layout.rs`); a viewport builder takes the saved size or position only when the window opens, never a per-frame value.
Collapsed: thickness `ICON_SIZE` with no extra margin, only Expand is
visible, with no target or room reserved for Detach; title centered in the remaining
space (vertical for PM/OM). Attached and expanded: Detach and Collapse;
detached: Reattach only, with no system decoration. An OS close
reattaches. Reuse the contents of each surface and the reads/queries
of `window_detach.rs`; the Python engine stays in the main AppState.

- Project Manager (#170, point 4): its selection is a set of `PmEntry` (`Folder(NodeId)` or `Window(Tab)`), never `Tab`s alone; a row gesture goes through `select_gestures` (folder and window), a single click (window or folder) **only selects** (#423, S-K3/S-K4: the rule holds for every tree): opening is the double-click, Enter or the menu, folders toggle on the triangle, the double-click (one toggle), Enter and → / ←, no slow-click rename (F2 or the menu), `open_requests` stays reserved for windows, paste targets `paste_parent` (the single selected folder, otherwise the root; the target then expands). Cut (Ctrl+X, menu) + Paste moves through `Action::CutObjects` / `MoveObjects` (mark `AppState::cut_objects`, rows dimmed through `PmInteraction::cut`). A drag moves too (#425): payload and feedback in `app/project_dnd.rs`, decisions pure in `stokesforge-app-state/src/tree_drop.rs`, checks shared with Paste in `AppState::check_move_into` (never a second copy). Every folder is shown sorted until a drop between rows puts it in manual order (`Tree::displayed_children`, `Command::SetFolderOrder`); anything that lists the project tree for the user goes through `project_tree()` / `displayed_children`, anything that mutates uses the model order (`children`). A folder copies and duplicates like any node (#391).
- Keyboard navigation of lists (#170, point 6, S-K9): ↑ ↓ Enter of a manager go through `list_row::read_navigation` (registry `KEY_ARROW_UP`/`DOWN`/`ENTER`, Shift and Alt+↓ variants consumed first, with no effect) and `list_row::neighbour` over the **visible** rows recorded at paint time, never over an order that counts the rows of a collapsed folder; the focus outline of a row is `list_row::paint_focus_outline` (never a hand-written `rect_stroke`). A new list manager follows this contract, and a keyboard shortcut read outside the registry stays forbidden.
- Menus (#114, #152): the grammar of `docs/menus.md` is the single source
  — sections in canonical order (main, create, clipboard,
  organize, delete, exit, `Properties…` last), separators placed
  **only** by `MenuSections::section` (`app/menu_sections.rs`, guard
  `no_raw_separator_in_a_menu`, no exemption), submenu
  only for an exclusive choice or ≥ 3 entries (never for 1 entry; 2 entries stay flat),
  depth 2, entry *absent* (not applicable) or *disabled with `.disabled`*,
  bare verbs, disabled header reserved for the graph, shortcuts through `SHORTCUT_*`,
  no icon and no Undo/Redo on right-click. The shared painters (`object_menu`,
  `object_node_menu`, `object_manager_settings_contents`,
  `columns_menu_contents`/`column_type_role_menus`/`plot_menu`,
  `graph_properties_menu`) paint the **content**: the top menu
  wraps it in a submenu that names the target, the right-click shows it
  flat. Check boxes are limited to real display toggles and leave the
  menus open; an action or an exclusive choice closes the chain. Do not
  create a parallel mutation path.
- Menu bar (#343): switching on hover from one title to another is a single
  helper, `toggle_on_hover` (`app/menus.rs`), called after all the titles
  (each `*_menu` returns the `Response` of its title); egui does not do it for
  the titles of the bar. An open title is recognized by the identifier of its
  popup (`Popup::is_id_open(ctx, Popup::default_response_id(titre))`), never
  by `Popup::is_any_open` (an open context menu would make the
  bar switch); no state in `AppState`. Do not leave the diagonal tolerance
  to `Rect::intersects_ray` alone: it ignores the other axis when the
  direction is exactly horizontal or vertical (guard in the helper).

## New graphs and detached windows

## Interface: wiring not to forget (detached window, layer, dialog)

Rules moved out of the skill `stokesforge-feature` (F1, #301): the skill no longer carries a rule, it points here and to `docs/`.

- **Detached view**: a single implementation per content (`book_contents`, `graph_view_contents`; `note_contents` and `matrix_contents` are floating only, since only the workbook and the graph detach, `Tab::is_detachable`, #473), called from both sides; do not reintroduce a second one. The detached view has **its own** `AppState`: an interface state added to `AppState` (edit in progress, confirmation, renaming…) exists there only if it is copied by `fork_for_detached_view`, resynchronized by `sync_detached_snapshot` / `sync_detached_sheet_editor` or brought back by `adopt_detached_book_view`; otherwise the gesture works floating and not detached (observed on sheet renaming, #106). `collect_shortcuts` reads the input of the root viewport: a global shortcut does not act in a detached OS window without its own wiring (#459: only Ctrl+Z, Ctrl+Y and Ctrl+S have it, `shortcuts::read_detached_history_and_save`, called at the top of each detached closure before anything is painted and queued after the window's own actions; Ctrl+Shift+S is consumed and dropped; Ctrl+Q is consumed with a band, `refuse_quit_in_detached`; a new global key stays in the main window), and `active_book` falls back to "the only detached workbook" even when a graph is active — a workbook shortcut can steal a key there from another context (F2 of the Object Manager). The editors and the focus of the Project Manager are indexed by viewport in egui's memory: compute the IDs **before** a `Context::data_mut`, with no call back into the context under its lock. Extra sharing of code is fine when it does not run into the `'static` constraint of `show_viewport_deferred`; say so in the report ("I factored X" or "I had to modify both implementations because Y").
- **Layer** (#167): a layer is identified by its index in `PlotSpec::panels`, never by `(row, column)` (several layers overlap in the same cell, and the rank in `DrawnPlot::panels` skips layers that are too small). An action without a clicked target (drop, "Send to", Add Text, New Layer) takes the **active layer** (#161), published in the `Context` and read by `graph_window::published_active_panel`, identical in a detached window; a gesture on an object carries the index of its layer up to `PlotEdit::selected_panel`. New layers are appended last (`compose::insert_cell`, `AddLayer`), so existing indices do not move; deleting a layer (`compose::remove_cell`) shifts them, and `StokesForgeApp::follow_layer_changes` carries framings, active layer and selection (#357). A gesture that adds series reuses the `Action` of the drop (`state::drop_payload_action` for columns, `drop_rows_action` for rows at x', #166): no second way of adding a series.
- **Failure of a dialog gesture**: `AppState::fail` writes it into the footer outright while a content dialog is open (`dialog_error`, S-M7), never into `status`; a state test reads `state.dialog_error()`, and a decision "did the gesture fail?" reads `gesture_failed`, never `status().is_error`.
- **Gesture outside the main window while a dialog is open (#471)**: `AppState::open_dialog()` (closed enum `OpenDialog`, state-based, never paint-based) is the single signal; the root publishes it (`window_band::publish_dialog`) and a detached viewport reads it with `window_band::main_dialog` (`None` in the root). The root refuses the actions of detached windows and panels in `accept_detached_actions` and says it through `AppState::refuse_outside_main` (status bar and history, warning; never `warn`/`fail`, which would wipe or hijack `dialog_error`) plus the band of that window (`app/window_band.rs`, overlay, 5 s, one wake at the deadline). A message of a drained action reaches the band through the origin ranges (`action_origins`) and `AppState::recorded_count`; information never shows in a band. Typed text in a detached cell or header goes through `window_band::refuse_entry`.
- **Grid context menu**: "Paste" is never disabled (probing the system clipboard at every frame would cost more than trying on click); the other deliberate gaps between menu and keyboard are in `docs/application/grid.md`, "Grid context menus". A menu toggle test makes two clicks in the same menu, then an action after a repaint with no event: neither the sheet nor its parents must stay open (`PopupCloseBehavior::CloseOnClickOutside`).

## Analysis (#181)

- Analysis, numerical computation (#332): `stokesforge-analysis` **never** calls the std `f64::exp/ln/powf/sin/cos/tan/…`, which delegate to the platform libm (MSVC CRT ≠ glibc to the last ulp: an iterative fit converged on Linux and not on Windows); it goes through the `libm` crate (`libm::exp`, `libm::log`, `libm::pow`, `libm::atan2`…), pure Rust, same bits everywhere. `crates/stokesforge-analysis/clippy.toml` (`disallowed-methods`) guards it, tests included (`--all-targets`): no `allow`. `sqrt`, `abs`, `floor`, `min`, `max`, `powi`… stay allowed (exact or without libm). A value frozen by `to_bits()` (`tests/determinism.rs`) is the proof; a test series whose convergence depends on the last ulp is chosen among those that converge, never by loosening an expectation.
- Analysis (#181): a calculation (`Tree::calculations`, link operation → series → output columns) is not a node; its creation, modification and deletion are undoable commands (`AddCalculation`/`UpdateCalculation`/`RemoveCalculation`), the recalculation is derived (outside the history, like formulas) and its trace lives in `outputs`, never on the column. A calculated column is read-only (cells, type, deletion of cells; a formula column too: cells and type, #431 — `Command::SetColumnType` refuses with `FormulaColumnReadOnly`, `Project::set_column_type` stays open to the recalculation, and the Type menu entries are greyed with their reason (`AppState::column_type_lock`); its metadata other than the formula stay free). The caps on the settings (degree, iterations, noise) are checked by `Operation::validate` in `ops::run`, for the interface, `pyst` and the file. **Bounds and prerequisites (#260): a single source, `stokesforge-analysis`.** The caps are public constants of `ops` (`MAX_DEGREE`, `MAX_ITERATIONS`, `MAX_PEAKS` = 100, `MAX_COMPONENTS`) that `validate`, `deconv` and `Model::compile` (which refuses a degree beyond the cap, before any allocation: a degree read from the preferences must not build anything) read, and that the quantity table (`quantities.rs`) also reads: never a literal `9`, `50`, `4` or `5000` in a `between(…)`. What is missing before a calculation without reading any data (points, zone, unreadable or parameterless model) is `Operation::readiness()`, a data `enum` (`Readiness`) that the app maps to cases through `analysis::issue_of`, exhaustive `match` without `_`; the form draft is described as an `Operation` even when incomplete (`draft_operation`: a point or a zone not yet set is a `NaN`). What reads the `Tree` (`NoSeries`, `NeedsReference`/`NeedsResponse`, `MissingColumn`) stays in the app. The automatic estimate of the starting values is `FitSpec::auto_initial(series, range)` and "forget the positions" (recent analyses) is `Operation::forget_positions()`: the app rewrites neither. `pyst.analysis.readiness(kind, **options)` (#331) reads `readiness()` without writing anything, with the same rule (`baseline`, `integrate`, `fit`; the others are always ready). The form is `stokesforge-app-state/src/analysis.rs` (without egui), the window and the Results pane in `src/app/analysis_*.rs`/`results_pane.rs`, `pyst.analysis` in `stokesforge-script/src/analysis.rs`. Categories and recent analyses (#248, #249): the menu sorts the methods by `Category` (`analysis.rs`), one window per category; the three most recent analyses (`analysis_recent.rs`) live in the preferences, never in the `.stf`; the click on a category of the right-click reopens the last method of the category (`analysis_menu::category_preset`, published in the `Context`). The header rows Metadata / x' are set per workbook (egui memory, `grid::header_rows`) and, for new workbooks, by preference (`workbook_show_*`): a per-document view setting follows this pattern, never a global flag. The reference of a `Correct` is frozen in the hidden workbook of copies (`stokesforge-core/src/analysis_store.rs`) and the originals of a replacement are kept there (`Command::RestoreOriginalData`). Adding an operation: analysis crate → `compute` → form → `analysis-*` keys en/fr → `pyst.analysis` → `docs/tests.md`. An operation that transforms the curve and can **replace** the Y (baseline, correction, smoothing #324) writes an output whose key is `replacement_key` (`corrected`, `smoothed`, `stokesforge-core/src/calc.rs`); add it to this function, to `replacement_disabled`, to the guard of `persistence/src/calculations.rs` (traces) and to the list of preview keys (`analysis_preview.rs`). Name of the output columns (#256): **a single rule**, `stokesforge_core::OutputName` (`of`, `english`), with `output_unit` (always the unit of the source), `family_english` (comment) and `wants_output` (which output is written, `PeakOutputs` for the two peak check boxes); the app translates it through `output_name_text_in`, exhaustive `match` without `_` to `analysis-output-*`, `pyst` writes `english()`. Never a `format!` of an output name elsewhere; a new output = a variant, its `en`/`fr` key, a line in `tests/output_names.rs` (`rank` and examples). The name stays frozen at creation (invariant 11: the recalculation rewrites only the data).
- Analyzing a row (#253): never an analysis "on rows" — a row is **transposed** into a linked sheet "Sourceᵀ" (`Command::TransposeRows`, `Tree::transposes()`, `stokesforge-core/src/transpose.rs`), then its column "Row N" is analyzed like any other column; the gesture (`AppState::open_row_analysis`, `Action::OpenRowAnalysis`, or `OpenGraphAnalysis` on "row" curves) opens the group `MacroKind::AnalyzeRows`, which the (modal) analysis window closes at Apply and aborts at Cancel. The link is a **recomputable snapshot**: *stale* and *modified* are derived from the tree (versions and x' read, content fingerprint `content_stamp`), never stored, outside targeted recalculation. All the data read by the transposition enters `TransposeLink::inputs`; every write goes through the `Project` primitives (new version). A refusal names the column by its **letter** (`CoreError::TransposeNoXPrime` / `TransposeNotNumeric`). A new surface that creates columns from the source follows this path, never a direct write.
- Warnings and series length (#313): a calculation that degrades a result **says so** through a `Warning` (data, never a sentence) and does not crash (invariant 10); a new `Warning` has its row in four tables with exhaustive `match` (`persistence/src/calculations.rs`: recording, reading, rank and file name; `analysis_dialog.rs::warning_text`; `pyst` `analysis.rs`) and its `analysis-warning-*` key in `en` and `fr`, with a `.stf` round trip (`persistence/tests/calculations.rs`). A division by an exact zero is counted (`DivisionByZero`) and returns `NaN`. A calculation on two columns of different lengths reads the length of **X** if given, otherwise that of Y (`read_pair`); in a replacement, an output shorter than Y keeps the original cells of the rows beyond X.
- Constrained polynomial on a shifted X (#296): the centering of X (#283) applies only to the QR path (without constraint). A constrained polynomial goes through Levenberg-Marquardt **without centering** — a fixed coefficient changes meaning in the centered frame — and carries `Warning::ShiftedX` (`FittedSeries::shifted_x`, `CompiledModel::x_shift_is_large`, threshold `X_SHIFT_WARN_RATIO`) when the mean of X exceeds 100 times its extent. Documented limit, not a defect to fix.


- Definitive corrections (#212): `ReplaceAnalysisData` writes the Y and their
  `CorrectionRecord` in the same history step. The trace is separate from the
  calculations, persisted in `correction_traces` (`CorrectionTraceRecord`, originals as `OriginalRecord` pairs), immutable and kept even after
  the user edits the column; a column corrected several times keeps **a single** raw
  data item (the one from before the first correction, #308) and "Restore Original
  Data" returns it whatever the trace, removing the column from all of them; never create a calculation whose output is its own source.
  A trace discarded at read time is counted in `LoadReport::discarded_corrections` (#309); discarded calculations and traces are reported in **one** message (`status-load-discarded*`), and saving over the source file of a read with discards asks first (`Action::ConfirmDiscardedSave`, window `stokesforge_discarded_save`).
  The destination choice uses `ChoiceOption::disabled` for read-only
  sources; sources traced several times require `modal_confirm`.

## Errors: raw English below, catalog sentence in the application

The `Display` (`#[error(...)]`) of the lower crates (core, commands,
persistence, import, script, render-svg…) is **raw English**, concise and
readable by a user of the CLI or of `pyst`: it is never translated and none
of these crates depends on Fluent. The application phrases every displayed error
through `crates/stokesforge-app-state/src/errors.rs`:

- one function `error_message(&Erreur) -> String` per family
  (`errors::model`, `commands`, `session`, `file`, `import`, `formula`,
  `number` (a typed number out of the `f64` range, shared by formulas, cells and
  custom Fit models, #429, #438: the model check lives in `Operation::readiness` only,
  never in `Expr::parse`, `Model::compile` or `validate`, which stay lenient for stored models),
  `render`, `export`, `script` under the `python` feature);
- each variant → one key `error-<family>-<cause>` of the `en` catalog, its
  fields as named arguments (`tr!("error-file-corrupt", path = …, detail = …)`);
- the `match` is **exhaustive, without `_`**: a new variant does not compile
  until it is mapped. With no sentence, `errors::fallback` returns
  its English `Display` (nothing disappears);
- the test of the family builds a value of each variant and checks
  non-empty sentence, no jargon (S-R9), no final period: add one for the
  new variant;
- a `detail` (cause described by the originating crate) or a system message
  is taken as is, in English;
- **never** `to_string()` nor `{err}` of an error shown to the user.
- a `std::io::Error` goes through `errors::io::error_message(&err)` (keys
  `error-io-*`), and the context message receives it as a variable
  (`tr!("error-template-export", cause = …)`). `ErrorKind` is
  `#[non_exhaustive]`: this family keeps a fallback `_` (`error-io-other`),
  the only exception to "without `_`".
- a formula the F(x)= field **keeps** (#433) says why through the same
  `errors::formula::error_message`, as a failure on the status bar and as the
  tooltip of the frame (`AppState::formula_issue`, memoised by revision and
  epoch, the error kept and the sentence built afterwards so that a language
  change follows). `FormulaError::Parse` is mapped to `error-formula-syntax`,
  which holds **no `detail`**: the parser's raw text stays in the `Display` for
  the CLI and `pyst`;
- the status bar messages (`AppState::notice` / `warn` / `fail`) go through
  `tr!` (keys `status-*` for information or a warning, `error-*`
  for a failure); the guard `no_hardcoded_label` covers `notice`, `warn`, `fail` and
  `progress`.
  **One rule for the line (S-R18, #453)**: red = not done, orange = done but not as asked or needs your eyes, plain = done as asked. A message takes the line by that rule (most serious of the gesture, last on a tie; a plain message with no gesture never replaces orange or red), so a gesture says its messages in any order: no "set it last" trick, no `paste_warnings`-style buffer. A new emitter outside `dispatch` that says several messages wraps its body in `AppState::gesture`; a poll or timer in `AppState::background`; a progress line is `progress`, never `notice`. Orange fades after 30 s, red stays. A script exception reads "Script failed. See the console" (S-M10).

Same pattern for the **names of analysis output columns** (#256): the core
returns a data item (`stokesforge_core::OutputName`, with `english()`), the application
phrases it through `analysis::output_name_text_in` (exhaustive `match` without `_`
to `analysis-output-*`), and `tests/output_names.rs` guards the agreement of
the catalog's English with `english()`: changing one of these texts means changing
both.

Wording: what happened, then what to do only if useful;
Sentence case, no final period on a single line, no "please", no
apology, no internal jargon (*node, session, macro, command, tree*). A wrong
or ambiguous message is fixed in the catalog (`en`), not in the lower
crate — unless the raw English text itself is wrong.

- `pyst` (#399): `set_graph` is a size door like the Graph Properties draft and `Action::SetFrameSize`: the size keys call the `compose` setters in the same `SetPlotSpec`, fix a legacy graph inside `prepare`, take their unit from the `unit=` keyword (never the Preferences) and refuse out-of-range values; `pyst.graph_size` reads `figure_layout` and never writes. `LengthUnit` lives in `stokesforge-plot`. #411: `set_graph` also switches the layer placement (`stokesforge_render_svg::set_layer_placement`, shared with Graph Properties) and sets a free layer through `compose::set_free_frame`.
- `pyst`: **frozen API V1 (#331), alpha (`pyst.__api_version__`, #356)**. The reference list (names, signatures, exceptions, option keys, keys of the returned dictionaries, enumerated values) is the "Frozen API V1" section of `docs/python-and-scripting.md`, in `pyst-api` blocks read by `stokesforge-script/tests/frozen_api.rs`. Any change to this list — additions included — is an explicit decision (issue or agreement of the user) made **in the same commit** as the code: update the list first, then bump `PYST_API_VERSION` and add the snapshot `stokesforge-script/tests/api-witnesses/vX.Y.txt` (`scripts/versions-aligned.sh --pyst-snapshot`) in the same commit (0.x: minor +1 for any change; rules in `docs/python-and-scripting.md` § API version). An option added to `plot`, `set_graph` or `set_column_meta` enters its constant (`PLOT_OPTIONS`, `SET_GRAPH_OPTIONS`, `COLUMN_META_FIELDS`, which feed the unknown-key message) and the `options` block; a parameter is named in English (`path`, `handle`, `values`); docstrings and error messages in English (docstrings since #376).

## Rendering: silent pitfalls

- Rendering: **a screen marker** (red frame, handles, selection highlight) is painted over the cached figure, in the application: it enters neither the cache key nor the pipeline, so never the SVG/PDF/PNG export (`docs/rendering.md`, § Visibility and selection (#81–85), selection handles).

- Rendering: `plotters` is taken **without its fonts** (`default-features = false`). A `DrawingBackend` that does not override `draw_text` **panics** at the first tick, and one that does not override `estimate_text_size` measures the text by the number of UTF-8 bytes — silently. Every measurement goes through `stokesforge_render::text` and nowhere else (`architecture-choisie.md` §4.3/§4.4).
- Rendering: **a plotting feature never goes into a single backend** — it goes into `stokesforge-render`, which is generic over the backend. Corollary of the same pitfall: the Plotters elements that measure text themselves (`configure_series_labels`, `MultiLineText`) go through `FontData::estimate_layout`, hence through the naive heuristic, **not** through `estimate_text_size` — the legend is written by hand for this reason (`stokesforge_render::legend`).
- Rendering: **every title, axis title and legend entry goes through Typst, ticks never** (issue #32). The role is decided in the pipeline by the style (`formula::rich_style`), and both backends switch on `formula::is_rich` at measurement **and** at drawing — never on the presence of `$`. These texts are therefore Typst markup: a text taken over automatically (column name) must be escaped upstream.
- Rendering: **the size of a figure has one source**, `pipeline::figure_layout` (#394): the **plot areas** stored in `PlotSpec::frame_widths` / `frame_heights` (sanitized by `sanitized_frame_widths()` / `sanitized_frame_heights()`) plus the margins, axis bands and title bands the cells ask for (aligned across a column and a row), with **rounded prefix-sum breakpoints**; adding an axis or a title grows the image, never the frame. Screen (`GraphView::figure_layout`), the three exports (`render_svg::figure_size`), the figure copy, `pyst`, the PNG labels and the window's ratio read it; never `DEFAULT_FIGURE_SIZE` as "the size" (it is only the **legacy** meaning of empty vectors, fixed for good, invariant 12). Rounding each size alone, or cutting cells with `split_evenly` for a stored size, makes screen and export differ.
- Rendering (#394): a size edit goes through `Action::SetFrameSize` / `SetGridFrames` / the Graph Properties draft (`frame_sizes::set_size_in_draft`); a legacy graph (nothing stored) is given the frames it is drawn with **in the command of its first edit, whatever it is** (`AppState::with_fixed_frames`, `bridge::set_graph_spec`), never at load; `compose::insert_cell` / `remove_cell` insert or remove a whole grid column or row with its frame. Core never measures text.
- Rendering (#405): "Figure size = Fixed", Left and Top (`PlotSpec::fixed_figure`, `figure_left`, `figure_top`) are floors on the gutters of `ExplicitGrid::build` (the explicit path only, never the legacy one); a title is never in the reserve; the overflow is `FigureLayout::fixed_overflow`, said by `status-figure-grew` (status bar in `AppState::execute`, note under Size). Left / Top edits go through the draft (`frame_sizes::set_offset_in_draft`) or `pyst`; there is no mouse handle for them (removed in #426: layers and the figure are moved and resized with the mouse only in the Page Layout Mode).
- Rendering (#398): **free layer placement** (`PlotSpec::layer_placement`, `PanelSpec::free_frame`) is a second layout of the same `figure_layout` (`FreeLayout`); a Free graph is never legacy (`frame_sizes::is_legacy` false) and no path (`with_fixed_frames`, `fix_new`, `bridge::set_graph_spec`, `fix_legacy_frames`) may give it grid frames. Switching goes through `frame_sizes::set_placement_in_draft` (grid to free: nothing moves; free to grid: `compose::set_grid_placement`, L7 then C4), the fields through `free_fields` / `set_free_field_in_draft` (Left / Top are stable page coordinates, as stored), Add Layer Beside through `frame_sizes::place_beside` inside the same `AddCell`. Stacking (#398 batch 2a): `FreeFrame::stack` orders the drawing (`PlotSpec::free_draw_order`), `bring_to_front` / `send_to_back` rewrite the keys of all cells to `0..n` and keep layer numbers, a new cell is created in front, the graph title anchor reads layer 0, `DrawnPlot::panels` stays in spec order (use `DrawnPanel::cell_rank` for the drawing order) and anything under the outer rectangle of a higher-ranked cell is not pickable (`hit::front_to_back`, `panel_at`); Auto layer background paints only over an overlap. No mouse handle on a layer outside the Page Layout Mode (#426; `GraphView::layout_is_free` still serves Shift + click); hit-testing follows the drawn plot areas, never grid breakpoints.
- Application (#394): a graph window **follows its figure** (floating: `window_stack::follow_figure`; detached: `follow_figure_in_viewport`) by comparing the published figure size with the previous one (`FigureFollow`, `window_placement.rs`) and moving by the difference at the display scale it had, top-left fixed, clamped to the workspace or monitor; maximized windows do not resize and the first frame of a graph never does. It lives in the shell (invariant 2), never in app-state. The Page Layout Mode previews through `FramePreview` and commits `Action::SetGridFrames` / `SetFreeLayout`; no other gesture resizes a cell.
- Rendering: the lever `TessellationOptions::feathering` lives in `stokesforge_render_egui::feathering`, as a free function on the `Context`. It is **not** in the cache key and must not enter it (`architecture-choisie.md` §4.2, locked by `stokesforge-render-egui/tests/feathering.rs`). Its trigger, dragging, is wired in `stokesforge-render-egui/src/lib.rs` since R7.3.
