## New graphs and detached windows

- Graph composition (#257): the rules that build series from the columns of a workbook live in `stokesforge_core::compose` (`series_from_columns` for the nearest Y→X / Y2→X2 pairing **to the left** and the palette by rank, `x_for` for the abscissa alone, `row_series` — the translated name is a parameter, never `tr!` in core —, `overlay_base`, `role_layer_of`, `overlays_full`, `current_plot_spec`, `panel_plot_type`), shared by the application (`AppState::plot_columns`, `add_series_to_graph`, `add_layer`, `add_rows_to_graph`, `plot_rows`: they only emit the command and the messages), `pyst.plot` and the appendix of an analysis. A new series goes through `SeriesSpec::from_palette(y, rang)`, never `palette_color` / `LineSpec::from_palette` written by hand; an overlaid layer is named (`OverlaySpec::role_layer(n)` for Xn/Yn, n = 2 to 4 — `SECOND_AXES` for n = 2 —, `TOP_X` for the lines layer — its Y stays on the left, on purpose —, `OverlaySpec::new` for the rest), never a literal `{ x_top, y_right }`. `pyst.plot(y)` without `x=` looks for the abscissa by role like the window (`docs/python-and-scripting.md`). Error columns (#360): `series_from_columns` and `errors_for` pair the first `YError` / `XError` column to the right of a Y (Y2–Y4 too), before the next ordinate column, into `y_error` / `x_error`; `pyst.plot` applies the same rule unless `x_error=` / `y_error=` is given (`None` goes without); the "Y error" / "X error" series fields change it per series (never propagated to a group); the renderer draws whiskers on every type from the error column alone.
- New graphs (#103): no default title, demo included; `name` names the node and its window, never the figure. Keep the possibility of typing a title, without hiding `title_visible`. The explicit titles of `stokesforge-render::sample` are rendering witnesses, not user defaults.
- Detached windows (#104): publishing a snapshot does not wake the `show_viewport_deferred` callback. `app/window_detach.rs` compares epoch, data revision and geometry revision, then requests a repaint of the reader viewport; a mutation applied after painting schedules the root publication frame (end of `ui()`, `app.rs`). Tests: `app::window_detach::tests`, `app::tests`. The Project Manager also follows its selection, its hiding and the active tab. No periodic wake-up at rest.

- Dialogs and detached windows (#472): **a content feature works everywhere, a global feature stays in the main window.** Every dialog is painted by the root (`show_edit_dialogs`, `confirmations::show`), never in a viewport closure; a detached window only queues actions and shows a band (`announce_opened_dialog`). The single written exception is object properties (rectangle, arrow), which stays in its graph's window. A key consumer (`collect_undo_redo_shortcuts`, Esc) stands aside with `modal_shown`.

## Interface: wiring not to forget (detached window, layer, dialog)

Rules moved out of the skill `stokesforge-feature` (F1, #301): the skill no longer carries a rule, it points here and to `docs/`.

- **Detached view**: a single implementation per content (`book_contents`, `graph_view_contents`; `note_contents` and `matrix_contents` are floating only, since only the workbook and the graph detach, `Tab::is_detachable`, #473), called from both sides; do not reintroduce a second one. The detached view has **its own** `AppState`: an interface state added to `AppState` (edit in progress, confirmation, renaming…) exists there only if it is copied by `fork_for_detached_view`, resynchronized by `sync_detached_snapshot` / `sync_detached_sheet_editor` or brought back by `adopt_detached_book_view`; otherwise the gesture works floating and not detached (observed on sheet renaming, #106). `collect_shortcuts` reads the input of the root viewport: a global shortcut does not act in a detached OS window without its own wiring (#459: only Ctrl+Z, Ctrl+Y and Ctrl+S have it, `shortcuts::read_detached_history_and_save`, called at the top of each detached closure before anything is painted and queued after the window's own actions; Ctrl+Shift+S is consumed and dropped; Ctrl+Q is consumed with a band, `refuse_quit_in_detached`; a new global key stays in the main window), and `active_book` falls back to "the only detached workbook" even when a graph is active — a workbook shortcut can steal a key there from another context (F2 of the Object Manager). The editors and the focus of the Project Manager are indexed by viewport in egui's memory: compute the IDs **before** a `Context::data_mut`, with no call back into the context under its lock. Extra sharing of code is fine when it does not run into the `'static` constraint of `show_viewport_deferred`; say so in the report ("I factored X" or "I had to modify both implementations because Y").
- **Layer** (#167): a layer is identified by its index in `PlotSpec::panels`, never by `(row, column)` (several layers overlap in the same cell, and the rank in `DrawnPlot::panels` skips layers that are too small). An action without a clicked target (drop, "Send to", Add Text, New Layer) takes the **active layer** (#161), published in the `Context` and read by `graph_window::published_active_panel`, identical in a detached window; a gesture on an object carries the index of its layer up to `PlotEdit::selected_panel`. New layers are appended last (`compose::insert_cell`, `AddLayer`), so existing indices do not move; deleting a layer (`compose::remove_cell`) shifts them, and `StokesForgeApp::follow_layer_changes` carries framings, active layer and selection (#357). A gesture that adds series reuses the `Action` of the drop (`state::drop_payload_action` for columns, `drop_rows_action` for rows at x', #166): no second way of adding a series.
- **Failure of a dialog gesture**: `AppState::fail` writes it into the footer outright while a content dialog is open (`dialog_error`, S-M7), never into `status`; a state test reads `state.dialog_error()`, and a decision "did the gesture fail?" reads `gesture_failed`, never `status().is_error`.
- **Gesture outside the main window while a dialog is open (#471)**: `AppState::open_dialog()` (closed enum `OpenDialog`, state-based, never paint-based) is the single signal; the root publishes it (`window_band::publish_dialog`) and a detached viewport reads it with `window_band::main_dialog` (`None` in the root). The root refuses the actions of detached windows and panels in `accept_detached_actions` and says it through `AppState::refuse_outside_main` (status bar and history, warning; never `warn`/`fail`, which would wipe or hijack `dialog_error`) plus the band of that window (`app/window_band.rs`, overlay, 5 s, one wake at the deadline). A message of a drained action reaches the band through the origin ranges (`action_origins`) and `AppState::recorded_count`; information never shows in a band. Typed text in a detached cell or header goes through `window_band::refuse_entry`.
- **Grid context menu**: "Paste" is never disabled (probing the system clipboard at every frame would cost more than trying on click); the other deliberate gaps between menu and keyboard are in `docs/application/grid.md`, "Grid context menus". A menu toggle test makes two clicks in the same menu, then an action after a repaint with no event: neither the sheet nor its parents must stay open (`PopupCloseBehavior::CloseOnClickOutside`).

- Application (#394): a graph window **follows its figure** (floating: `window_stack::follow_figure`; detached: `follow_figure_in_viewport`) by comparing the published figure size with the previous one (`FigureFollow`, `window_placement.rs`) and moving by the difference at the display scale it had, top-left fixed, clamped to the workspace or monitor; maximized windows do not resize and the first frame of a graph never does. It lives in the shell (invariant 2), never in app-state. The Page Layout Mode previews through `FramePreview` and commits `Action::SetGridFrames` (it carries `slack: Some(..)` for an outer-edge drag and for an L-corner drag, #505) / `SetFreeLayout` / `FitPageToLayout` and `FitLayoutToPage` (the Fit Page to Layout and Fit Layout to Page buttons and menu entries, #505; K1); no other gesture resizes a cell. **The page changes size only through the page tools** (L-shaped corners, Figure size field, Fit Page to Layout, P1), with **one exception**: adding or emptying a row or column (a drop into a band, a drop between two lines, a move that collapses a line, Delete Layer) changes the page by that row or column, after the new line has used the empty space of the grid on its axis (bottom then top for a row, right then left for a column; `compose::open_line` / `eat_slack`, fed by `frame_sizes::grid_gutters`, the one place); Ctrl at the press of a page corner keeps the page's ratio; an outer edge or Alt+line pulled outward at the page edge says so in the status bar (`GraphEvent::PageEdgeReached`, once per drag); **the L corners are page corners** (K1): they add or remove empty space and never scale or move a graph; only the Figure size field and Fit Layout to Page scale the graphs, and the padlock belongs to the Figure size field alone (Fit Layout to Page always scales one factor per axis): every other gesture of the mode changes graphs inside the page and stops at its edge. **Shift means snap and magnets off everywhere in the mode** (P2); the "row alone" drag of an internal line is read from Alt at the press. On a Regular Grid it also commits `Action::MoveGridCell` (#491: drag inside a graph or arrow key, `compose::move_cell`, one `MoveLayer` step); the four edge bands (left, right, top, bottom; #503) and the internal lines (#504, `stokesforge_render::grid_line_at`) are the drop zones of `stokesforge_render_egui::edge_band`, shared with the drop of columns (#357); they are computed from `FigureLayout::grid_outline()`, without the slack of #505, and the collapse of an emptied column or row is `compose::close_empty_lines`, shared with `remove_cell`.
