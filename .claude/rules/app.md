## Application (`stokesforge-app` and `stokesforge-app-state`): building blocks and guards

**Two crates, one boundary held by the compiler (#263).** `stokesforge-app-state` holds everything the application decides without drawing it: `state.rs` + `state/` (`AppState`, `Action`), `selection.rs`, `preferences.rs`, `analysis.rs`, `analysis_recent.rs`, `object_manager.rs`, `object_drag.rs`, `history_text.rs`, `quantities.rs`, `user_colors.rs`, `object_format.rs`, `text_format.rs`, `errors.rs`, `i18n.rs` + `i18n/` (the `.ftl` catalogs and `tr!`) and `file_picker.rs`; it has **no** egui/eframe/winit/wgpu dependency (`tests/no_ui_dependency.rs`, allowlist). `stokesforge-app` keeps `main.rs`, `app.rs`, `app/`, `theme.rs`, `icons.rs`, `field_state.rs`, `number_field.rs`, `toolbar.rs`, `list_frame.rs`, `tree_lines.rs`, `color_picker.rs`: everything that names an egui type. Interface logic that is decided goes in `stokesforge-app-state` (never `use egui`: the compiler refuses), drawing or a gesture goes in `stokesforge-app`. Imports are explicit (`use stokesforge_app_state::state::Action;`), with no re-export at the root, except `tr!` (`use stokesforge_app_state::tr;`). The system clipboard (`stokesforge-clipboard`) pulls in winit: the state keeps only neutral bytes (`state::FigureBytes`, an `ExportFormat` and its bytes), `app/figure_copy.rs` translates them to MIME types and phrases the error (`clipboard_error_message`). **`cfg(test)` pitfall**: `cfg(test)` applies only to the tests of the crate that carries it. What the state isolates under `cfg(test)` (preferences path `preferences::default_path`, starting language `i18n::startup_language`, `set_object_manager_open_for_test`) is therefore isolated under the `test-support` feature as well, which the dev-dependency of `stokesforge-app` enables: without it, the app tests (which build an `AppState` with `new`) would read and write the real `preferences.json` (locked by `stokesforge-app/tests/preferences_isolation.rs`). The integration tests of `app-state` do not see `cfg(test)` either: a dev-dependency of the crate on itself enables `test-support` (`tests/isolation_test_support.rs`, #329), without which `cargo test -p stokesforge-app-state` alone reads the real `preferences.json`. Never `test-support` in a normal build or in a `[dependencies]`. `fl!` reads the `i18n.toml` of the **calling** crate: the two `i18n.toml` files set the same `domain = "stokesforge_app"` and the one of the app points to the catalog of `stokesforge-app-state/i18n`.

A draft field (`number_field`, `edit_text`) is drawn under `field_state::for_target(ui, <target>, …)`, so its identifier holds the object it edits (axis side, series, box…), and a target pick (tab, list row, header) is applied **after** the page it governs is drawn, in the same frame, then `ctx.request_repaint()`: `field_state::pick_pending(ctx)` where the click is reported, `field_state::pick_allowed(ctx)` before applying (false when an unreadable draft refused the leave, #498). Never `push_id` around a `form()` for that (it resets the labels column and the scroll).

A drop target lights up its window border through the `file_drop` marker (`set_drop_target`, read by `show_window_in_layer`, the maximized area and the detached tab), with `theme::drop_target_stroke`, never a `rect_stroke` in the content (#386).

Transitions #72–#73: native Wayland is the default, `STOKESFORGE_X11=1` forces
X11; the `vendor/winit` and `vendor/smithay-clipboard` patches, outside the
workspace, share the drop receiver and the clipboard between viewports.
Choice, targeted `rustfmt` commands, manual verification and removal:
`vendor/winit/STOKESFORGE.md`. The exact parser and channel are tested by
`stokesforge-app/tests/wayland_{uri,bridge}.rs`. Frame starvation (#457): Wayland
has no occlusion event, so the vendored winit infers `Occluded` from a frame
callback that does not come while a redraw is wanted, only for a window that opts in with
`WindowExtWayland::set_reports_occlusion` (the root, on its first pass; never a detached
window: a reported window gets no pass and its input is dropped) (`frame_starvation.rs`, pure,
`tests/wayland_frame_starvation.rs`); that is what lets eframe keep running a
covered root, so a detached window may be maximised over it (Page Layout Mode).
Never a periodic wake for it (#104). Handing a gesture to the OS (`ViewportCommand::StartDrag` / `BeginResize`) goes only through `app/os_gesture.rs` (guard `no_os_gesture_command_outside_the_helper`): on Wayland the compositor keeps the button release, so the helper plays it for egui at the head of the next pass of that viewport (`Plugin::input_hook`); a plain send leaves the title "dragged", every second grab does nothing and hover extends the column selection (#457). Recheck on any eframe upgrade; real-compositor
proof: `tests/wayland_covered_root.rs` (manual, headless mutter, GL backend).
The empty graph goes through `AddGraph`; `SessionHandle::new_project`, like
`load`, replaces the identity and empties the history after confirmation in the UI.

- `stokesforge-app`: `app.rs` split (#115): real modules in `src/app/`, one per surface (module → role table in the code-split page of `docs/application/`), explicit imports, minimal visibility (`pub(super)`); `app.rs` keeps only the orchestration of the frame (`StokesForgeApp` and `new`, `ui()` and the panel order, `collect_shortcuts`, deferred actions, blocking confirmations, draining of detached windows). A menu entry goes in `app/menus.rs`, window code in `app/window_*.rs`, a new surface in its own module (model: `object_manager.rs`, `toolbar.rs`, `app/dialogs.rs`). Tests follow their code and are reread at every restructuring (scope by `perimetre`, tests by Sonnet, witnesses by mutation). Giant functions are split in place (#124), never moved: keep the nesting of egui Ui/IDs and the order of events. Locked: `no_global_import_outside_tests` (no `use …::*`, no exemption); every code-reading guard goes through the one reader `stokesforge-app/tests/support/sources.rs` (both crates, recursive, functions found by name; never `include_str!` nor a named file). Not seen by the guards: where a new surface should live. Module → role table: `docs/application/shell-and-code.md` § Code split
- `stokesforge-app`: every color setting goes through `color_picker::color_field` with the color's usage (`ColorUsage::Curves`/`Text`/`Background`) and the `PickerEnv` of the saved colors, never through a `#RRGGBB` text field. In a toolbar, the swatch is a small square preceded by an icon (`color_icon_button`, #89); in a form, `color_field` (label + square). Empty color = automatic, drawn as a square crossed by a red line; opacity as `#RRGGBBAA`; automatic text and scales follow `stokesforge_render::color::auto_ink` (white on a dark background).
- `stokesforge-app`: every window goes through the common block: `show_window_in_layer` (`app/window_chrome.rs`, content window), `modal_dialog_with` (`app/dialogs.rs`), `modal_wizard`, `modal_live_settings` (Close only, settings applied live), `modal_read_only`, `modal_confirm` / `modal_save_changes` / `modal_alert` (only for what Ctrl+Z cannot undo, `app/confirmations.rs`, #229). Each modal has a **nature** (`DialogNature`, S-F11, #300) that sets the footer, the size class (Small 480 x 170, Medium 480 x 420, Large 640 x 500), the initial focus and the default button; an interactive window takes a class or a free size justified by `// FREE-SIZE(#300): <why>` (`no_free_size_without_justification`); a new window is catalogued in `docs/windows.md` with its `stokesforge_…` identifier (`the_window_catalog_and_the_code_agree`). `no_window_is_a_raw_egui_window` refuses a raw `egui::Window`, even for a wizard. Not seen by the guards: whether the chosen nature fits the window; existing code that deviates is not a model.
- `stokesforge-app`: dimmed text is reserved for the **secondary**: `theme::secondary_text` (11 pt: help, reason, technical detail under a sentence) or `theme::dimmed_text` (normal size: empty state, "Calculating…", label beside a result). `no_weak_outside_the_theme` (#392) refuses a written `.weak()` but not a dimmed text on content the user must read (`docs/interface-standard.md` § Windows and dialogs, "Dimmed text"); copying a neighbouring dialog's `.weak()` is no justification.
- `stokesforge-app`: every icon goes through `icons::icon_image` / `icon_button` (`IconRole`, `tr!` tooltip mandatory; rules in `docs/icons.md`; `no_icon_outside_the_component`). **Every action has its logo** (#110): a polished icon in a fixed bar, the two-letter family logo otherwise; this does not force display in the menus. Not seen by the guard: restraint in the use of color.
- `stokesforge-app`: every interface text is a `tr!` key of the `en` catalog (`docs/ui-texts.md`), written in **both** catalogs `en` and `fr` in the same commit. Locked, no exemption: `no_hardcoded_label` (also `set_title` titles and visible `add_filter` names; technical extensions and acronyms stay) and `no_catalog_key_is_dead` (`tests/labels.rs`, reads both crates). Not seen: whether the wording follows `docs/ui-texts.md`.
- `stokesforge-app`: a toolbar is a variant of `toolbar::ToolbarId` whose content is written in `toolbar::bar_contents` with `ToolbarButton`s (icon of the common component, `tr!` tooltip) that push the `Action`s of the menus; never a second execution path nor a panel placed beside it. The bars are **fixed** (#108): content and place frozen in the code (`ToolbarId::row`), no move and no floating mode; only their visibility (View menu) lives in `preferences.json`, not in the `.stf`. `Tools` and `Text` are always drawn, buttons disabled with a tooltip when no window is concerned. The text format (`ToolbarId::Text`) writes Typst tags into the text through `text_format::apply` for bold, italic, color and the size of a passage; the **font** (and, for a title or the legend, the size) is a field of the zone (`TextFont`, `AnnotationSpec::font`, #77/#78), set by `StokesForgeApp::format_zone` — never a `#text(font: …)` tag in the content.
- `stokesforge-app`: common appearance (#169): tabs go through `tab_strip` + `TabStripSide` (one level `Top`; two levels: primary `Top`, secondary `Left`, only the content scrolls, S-L9, #393); a selectable list or tree entry through `list_row` (`app/list_row.rs`); a two-state setting is a `state_toggle` (`app/state_toggle.rs`, #426): ONE button, both labels always visible and fixed, current state highlighted, whole button outlined on hover (`paint_hover_outline`), never a button that renames itself nor two clickable halves. Locked: `no_selectable_button_outside_a_menu`, `no_separator_before_a_section_title`, `no_small_bold_outside_the_theme`, `no_weak_outside_the_theme`, `no_hardcoded_color_outside_the_theme`, `no_literal_add_space_outside_the_theme`. Not seen by them: the **four text levels** (`theme::section_heading`, `table_header`, `secondary_text`, `dimmed_text`; bold through `theme::bold` only, #170); **one row height** `list_row::LIST_ROW_HEIGHT` (24 pt) set by `with_list_row_height` / `raise_to_list_row_height` / `restore_row_height`, no new sub-`Ui`; a decorative step separator is a dimmed icon (`icon_image` + `help_icon_tint`); forms through `app/form.rs` (`form`, `Form::row`/`checkbox`/`note`/`section`, #227), never a collapsible section (S-L5) except `Form::collapsible` "Advanced" (S-L8, #344: closed, bottom of its section, all Auto, same grid); `choice` (radios for 2–3 options, list from 4), `menu_sections::menu_choice`, `toggle_texts` only for the analysis preview gestures (S-K7, marker `TOOL-IN-WINDOW(#299)`); widths `theme::FieldWidth`, gaps `theme::SPACE_ITEM`/`SPACE_SECTION`.
- `stokesforge-app`: every workspace key consumer (grid, Project Manager, any shortcut that acts on the main window's content and is painted before the dialogs) checks `!dialogs::modal_shown(ctx)` (#406); `focus_free` alone is not enough, egui drops the focus on Esc before the pass. Test it with a bench that paints the workspace then a modal in the same frame.
- `stokesforge-app-state`: a save or a gesture that may replace the project (`save`, `request_unsaved`) commits the open entries (cell, header field, note) in `AppState` first (`commit_open_entries`, #465/#466); never rely on a focus-loss action of the grid, since `blocking_confirmations` clears the actions: the grid and note field end a "click elsewhere" through the state (`commit_edit`, `commit_note_edit`), not by pushing an action. The shell does the same for the entries of detached windows (`commit_view_entries`, on Save, Save As, New, Open, Quit), which also closes the egui-side graph text editors through `commit_open_text_editors`. A refused entry stays open and is left out; autosave never commits.
- `stokesforge-app`: a field that opens in place goes through `app/inplace_edit.rs` (#224, contract S-T4: everything selected, Enter/click elsewhere commit, Escape cancels, Tab commits and moves to the next); a number input is read by `stokesforge_core::number_format::parse_input` (decimal comma, #223), never `parse::<f64>`; the tick separator is `PlotSpec::decimal_comma`.
- `stokesforge-app`: cell input and paste (#258): **a single rule** "text → cell value", `stokesforge_core::ValueBlock::from_texts(kind, &[&str]) -> (bloc, promoting)` — input (`commit_cell`) and paste (`value_block_from_tsv_column`) call it, never a second implementation in the app nor a detour through `MixedCell::from_text` (which keeps `inf`/`nan` as read, rule C2 of the type conversion). `inf`, `nan` and `1e400` typed or pasted stay text; dates are read only in a `DateTime` column. A paste that overwrites a `Mixed` column calls the repromotion (`auto_promote_mixed_column_if_all_numeric`) before closing its group, and stays one history entry.
- `stokesforge-app`: every number input goes through `number_field::number_field` and a quantity of `quantities.rs` (#220), never `DragValue`/`Slider` (`no_numeric_field_outside_the_building_block`); an input defect is drawn by `field_state` (#219).
- `stokesforge-app`: behavior standard (#217) — fields, messages, dialogs, confirmations, disabling, keyboard and mouse follow `docs/interface-standard.md`, the single source (codes `S-N1`, `S-F3`… and readable names: rule index of the page). Each section there is *in place* or *planned* (#219–#232): a planned rule already applies to all new code; a planned building block or guard does not exist yet. The commit that delivers one moves it to *in place* and updates the skills.
- `stokesforge-app`: every expanded tree (Object Manager, Project Manager) draws its L-shaped connectors through `tree_lines` (`begin_tree`, `tree_children`, `TreeBranch::mark`), never through egui's indent line (#112).
- `stokesforge-app`: scroll bars look only from `theme::scroll_style` (`no_scroll_style_outside_the_theme`); the room taken by a bar is `theme::scroll_bar_allocated_width`; a page that scrolls uses `theme::page_scroll_area()` (end margin `SPACE_SECTION`, #347); a raw `ScrollArea` carries `// RAW-SCROLL(#347): <why>` (`no_raw_scroll_area_without_justification`, which cannot judge the reason).
- Configuration folder (#332): one door, `stokesforge_import::config_dir::config_dir()` (`STOKESFORGE_CONFIG_DIR` if set and non-empty, else `ProjectDirs`; applies in production too); preferences, colors, recipes and recent import files derive from it, recovery is `recovery_dir()`. `ProjectDirs::from` is called only there (`stokesforge-arch-guard/tests/config_dir.rs`). Not seen by the guard: a test that redirects the folder sets `STOKESFORGE_CONFIG_DIR` **and** `XDG_CONFIG_HOME` (`directories` honors only the latter, only on Linux: on Windows the tests wrote into the real `%APPDATA%\StokesForge`), under a lock if the value is restored or once per process (`OnceLock`); models `isolate_recipe_store` (`stokesforge-app-state/tests/shell.rs`), `hermetic_configuration` (`stokesforge-script/tests/script.rs`); `config_dir_from(Option<OsString>)` is tested without `set_var`.
- `stokesforge-app-state`: a file dialog is a `file_picker::PickRequest`, and every request says which default folder it follows (`PickRequest::folder_kind`, exhaustive, no `_`, #148); the starting folder comes from `AppState::folder_candidates` (session memory, Preferences default, fallback) and is looked up on the picker's thread (`is_dir`, `set_directory`), never on the interface thread. Only a file dialog's answer feeds the session memory (`remember_picked_folder`). `rfd::` stays in `file_picker.rs`; tests inject the picker (`start_with`, `start_resolving`, `start_fake`), never a real dialog.
- Server thread lock discipline (#475): the thread of `app/server.rs` only `try_lock`s the shared `AppState`, does no heavy work under the lock (the autosave write runs with the lock released), executes no command and never drops a script engine; `poll_autosave` / `poll_script` / `poll_recalc` are called only in `app/server.rs`; the thread wakes the windows in one place (`wake()`, one `request_repaint_of`, only when the tick changed something, focus plays no part) and `logic` schedules no wake; a window callback never locks the shared state (it runs inside the root pass that holds the guard); on exit the guard is released, then the thread joined, before `session.shutdown()`. Locked by `the_background_polls_and_the_wake_live_only_in_the_server_module`, `the_server_thread_never_blocks_on_the_lock` and the embed test of `server.rs`. Not seen: what is called under the lock in `server_tick` (no heavy work), the cost of the post-recalc `refresh` on a big project (L4).
- Grid entry row (#440): the empty row always shown below the last data row is UI only. `AppState::row_count` keeps counting model rows; navigation and selection use `AppState::entry_row(sheet)` (never `row_count` plus one), column selections and Ctrl+A never contain it, and writing in it goes through the ordinary `SetCells` (no `InsertRows`). `Action::CommitCellAndAdvance` moves the cursor in its handler, after the commit is accepted.
- Window identity (#388): every `ViewportBuilder` starts from `app_logo::viewport()` (`no_viewport_without_identity`; it sets the `app_id` `stokesforge` of the desktop entry; egui copies the icon to child windows but not the id). The logo is read only at run time, from `<exe dir>/share/icons/hicolor/256x256/apps/stokesforge.png` (installed by `scripts/logo-dist.sh`); never `include_bytes!` it, never name `assets/logo` in code (a build without the folder must stay the same code; no test enforces it). A missing or unreadable file degrades (empty icon, no logo in About, one stderr line, invariant 10). The About texture comes from `app_logo::texture_image` (straight alpha), created once at the first opening.
