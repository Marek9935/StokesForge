## Copying objects and figures

- Columns copied or deleted with a formula or a calculation that reads them (#306): Ctrl+Shift+C opens "Values / Formulas" only if a copied column carries a formula (`pending_full_copy`, window `stokesforge_full_copy`); deleting columns, a workbook or a folder opens **after** the gesture the window `stokesforge_column_use` (`Undo` undoes the gesture, `Close` does nothing) if a formula with a letter that shifts or an analysis calculation (X, Y, σ, not the hidden reference of a correction) read them. A formula keeps the columns it reads **by identifier** (`ColumnFormula`, #321): the stored text is never rewritten, the displayed letters follow the columns (`Tree::formula_letters`, `#REF` when the column is no longer in the sheet), and the only letters-to-identifiers conversion is `Tree::formula_from_letters` (tests that build loops on purpose), `Tree::formula_keeping` for the header field and a paste (#433: what cannot be read is kept as typed and framed), or `Tree::formula_for_entry` for `pyst`, which refuses what does not read and a loop project-wide (#403) — never reread a displayed text to compute or to modify another field.
- Formulas that read another sheet or workbook (#403): a reference is **one argument** with its prefix glued to the column (`Sheet3!B`, `[Book2]Sheet5!B`, `'Blanc 2'!B`), allowed only as the read column of a column function (`at`, `max`, `min`, `mean`, `sum`, `std`, `integral`); the formula stores the **sheet identifier** in a side table (`ColumnFormula::remote_refs`), never a name, and the displayed prefix is regenerated from the tree (`Tree::formula_letters`: shortest unambiguous form, quotes through `formula::sheet_token`). Anything that asks "what does this formula read, and is it there" goes through `Tree::formula_inputs` (recalculation order and fingerprint, loop check, `#REF` message, column use) — never `formula.columns()` filtered by the own sheet. **Names compare ignoring case** (`stokesforge_core::same_name_ignoring_case`): `check_name_available` refuses a sibling that differs only by case for every node kind **except columns**, and every generator of automatic names (`next_window_name(parent, prefix)`, which also skips every child of the target parent, of any kind (a folder `Book1` included), ignoring case, on top of the project-wide window check (#437); `next_graph_name` ("<Book> plot N", falls back to `GraphN`), `next_child_name`, copy and transposed names, the analysis store, `Folder<N>`, `<name> copy <N>`) uses the same function; a loaded file may still hold twins, and a formula naming one is refused as ambiguous. A copy keeps a remote reference on the original unless the target sheet is part of the copy (then it reads the copy); an external paste turns it into `#REF`.
- Object copy (#105–106): `NodeCopy` and `InsertCopy` are generic, atomic, with new destination identifiers. Unique names per folder (case ignored except for columns, #403), canonical rooted paths; an ambiguous bare name is refused. The system clipboard reuses the `.stf` conversions, with no version number; graphs between projects with columns embedded in a persisted hidden workbook (#107), revealed by Show Data. A folder copies like any node (#391): what is inside the copy reads the copy (graph series, formulas, calculations and transposed sheets whose ends are inside; `insert_copy` renumbers after the node loop, never inside it, prefix order), the rest reads the original; **the rule covers the whole gesture, not one subtree** (S1): the roots copied together go through one `NodeCopy::capture_all` (one `inside` set, a cross-root calculation or transposed sheet travels with the root holding its first output or its sheet) and one `Command::InsertCopies` / `Project::insert_copies` (one id map for all the roots, hidden workbooks of an external paste inserted after all the roots), never one `InsertCopy` per root in a loop; the clipboard decodes the roots into one project (`decode_copies`); pasting with the copied folder itself selected goes beside it (`AppState::paste_objects`). F2 renames in the managers (#130) and edits in the grid (#143), depending on the focus, never the name of sheets, Ctrl+D of sheets stays specific to the workbook viewport.
- Cell copy (#259): the clipboard TSV (Excel/LibreOffice format, cells quoted if tab, line break or quote) lives in `stokesforge-core/src/tsv.rs` (`encode`/`decode`), not in the app; the app only chooses the copied cells. A missing cell is emptied **before** conversion to text (`cell_copy_text_in`), never by `.replace(MISSING_TEXT_DISPLAY, "")` afterwards (erases the non-breaking spaces that were typed).
- Overflowing paste (#311, columns changed by #495): a paste that goes beyond the last column **creates the missing columns** (Numeric, `Command::AddColumn` like Add Column, `AppState::paste_targets`), inside the `PasteCells` macro opened BEFORE them and before any header is written, at most `MAX_PASTE_NEW_COLUMNS` per paste; `external_paste_range_error` checks them as Numeric; the plain `status-paste-columns-added` says it. What stays beyond is **dropped and counted**: columns past the cap and header fields beyond Formula of a bottom-anchored paste. `warn_dropped(columns, fields)` (`state.rs`) says an orange (S-R18) that stays over the plain messages of the same paste, in any order; columns (`status-paste-columns-dropped`), fields (`status-paste-fields-dropped`) or both in one message (`status-paste-columns-fields-dropped`). A new overflow case goes through this function, not through a separate `warn`. The decimal-comma notice of `commit_cell` (`status-cell-decimal-comma`) stays plain, cell input only, never paste.
- Copy of a graph figure (#149): Ctrl+C on the active graph **with no selected object** and outside an input field, or Graph › Export › Copy Graph, offers SVG + PNG + PDF together through `stokesforge-clipboard` (`app/figure_copy.rs`); the graph is "Graph" and never "Figure" in the interface. No command and no history. Real Wayland, Windows and macOS are not run by the tests (`docs/application/graph.md`).
